# z_t 有响应，为何尚未形成稳定 3D AP 收益？（2026-10-13）

> 只读机制审计，不是新模型实验。本次重新计算已有日志/探针，不使用 GPU，不修改模型、训练配置、门槛或队列。

## 1. 先纠正命题与结论强度

目前成立的是「z 有因果通路、有可解码的部分对象语义、有部分局部分类收益」，**不是**「随机状态机制已完整有效，只剩 AP 没涨」。
最后完成的 A2-R ep6 机制门仍是 M1/M3/M4 FAIL、M2 PASS，排序补门 M1' PASS；这些是不同层次的命题。
我们定位到的主要断点是：**辅助可解码语义到验证高分峰、再到真实 anchor/3D 框收益的链条尚未打通。**

证据强度必须分层：
- **已实测**：验证集高分预算/峰位置泛化差；GT 格局部分类确有正收益；后续 AP 出现跨类抵消。
- **源码确认的结构限制**：语义监督头不部署；直接 residual 是另一个 1×1 读出，且同格同类所有 anchor 共用一个增量，不直接修框。
- **仍待预测级干预**：稀疏错误峰是否实际挤掉真框、各 IoU 误差分量/梯度冲突是否主因，以及随机状态是否不可替代。不能把这些推断写成已测根因。

## 3. 第一处已测断点：全局排序尚可，验证集最有价值的高分预算不足

同一 ep6 checkpoint、同一 val pipeline、同一 eval 网络模式，分别替换 train/val ann 文件；各 20 clips：

| 读数 | train split | val split |
|---|---:|---:|
| 对象格 vs 其他格排序 AUC | 0.9995 | 0.9305 |
| GT-shuffle AUC | 0.5091 | 0.4526 |
| recall@top-k 均值 | 0.3453 | 0.1033 |
| recall@top-k 中位 | 0.2917 | 0.0000 |
| top-k recall 为 0 的 clip | 3/20 | **11/20** |
| argmax 到最近 GT 格的曼哈顿距离，clip 均值 | 2.51 cells | **43.73 cells** |
| 该距离的中位 | 1.00 cells | 7.00 cells |

val 有 **7/20** clips 同时满足 AUC≥0.9 且 top-k recall=0；**9/20** clips 的逐 clip 平均峰距 >10 cells。
这不是「所有背景分数整体很高」：mean_bg_prob train/val 仅 0.00188/0.00120。
更贴切的签名是**大量背景容易压低，但少量高分峰没有稳定落到对象上**，而且包含远距错峰，不只是相邻一格的量化误差。
argmax 距离为格点曼哈顿距离，不是检测框中心欧氏误差；各 clip 含多个类通道，均值不能被误读为每个对象都偏移 43.73 格。

### 3.1 AUC 高为何仍可能没有实际候选收益？

AUC 问的是「随机取一个正格与一个负格，谁更高」，不是「最高分的少数格是否正确」。
本项目一张 216×248 图有 53,568 格，某类正格很少。数学反例：1 个正格低于 3,750 个负格、高于其余 49,817 个负格，
AUC 仍约 0.9300，但 top1 recall=0。这只是数学反例，不是模型实际 FP 数或 KITTI AP。
真实数据中的 7 个高 AUC/零 top-k clips 已显示同种指标分离，故不能以 AUC=0.93 宣称检测意义的机制已跑通。

**仍不能直接断言错误峰造成了 AP 的全部下滑**：该图属于辅助语义头，不是部署分数；必须在最终候选/NMS 前取证。

### 3.2 高斯半径并不把 exact-positive 掩码扩成整块

训练/探针均用 `target.eq(1.0)` 作正格；`gaussian.py:26–153` 的 `exp(-(dx²+dy²)/(2σ²))` 只有中心等于 1。
CPU 数学校验：radius=2 的单对象 kernel 有 25 个正支撑格，但**只有 1 个 exact-one 格**。半径改变软肩部，不把 25 格都算成正中心。
此前预登记将「通道总标记格数/高斯范围」解释成每对象正格宽容度的措辞不可靠；本次只纠正解释，不修改 frozen M1 门。
因此相邻一格错误需与大距离错误分开分析，不能用 M1 FAIL 单独宣称没有对象信息。

## 4. 第二处断点：机制探针的局部收益，不等于实际检测收益

### 4.1 M3 不是完全没作用，但它只回答 GT 位置上的代理分类问题

从原始 20-clip JSON 重算：
- residual 开启时 GT 格 class-CE 均值 **0.6024**；关闭 **0.7217**；off−on **+0.1193**（按 clip）。
- 按 100 个 GT 格加权的 CE 改善 **+0.0790**；**15/20** clip 改善、5/20 变差。
- 同一 checkpoint 的 pooled GT 格 head 类别命中率：off **72%**、on **76%**。

所以「z 一点信息都没有」不成立。但源码 `probe_semreadout_ep6.py:287–300, 594–617` 的 M3：
1. 对每类先取所有 anchor 的最大 logit（不同类可以来自不同 anchor）；
2. 只在已知 GT 正格计算跨类 softmax CE；
3. **不计背景、不检查该 anchor 解码框 IoU、不经过 top-k/NMS，也不使用实际逐 anchor sigmoid focal 评价口径**。

实际 detector 则逐 anchor sigmoid，按 score 做 nms_pre top-k，然后解码/3D IoU/NMS。
因此 M3 证明的是**局部分类支路有用途**，不是「完整预测增添了正确 TP」。不能拿 CE 下降直接解释 AP 应涨。

### 4.2 监督头和部署直接读出不是同一函数

源码 `semantic_readout_rssm.py:210–231, 464–557`：
- `sem_head = Conv3×3 + ReLU + Conv1×1`，训练 z 的语义辅助头；**不在检测 forward 路径**。
- `z_cls_logits = Conv1×1(z)`，单独学习的部署分类 residual。

「一个带邻域、非线性的 probe 能解码 z」不保证「另一个线性逐格读出能把同样信息用于 anchor 决策」。
这不是接线 bug，而是**监督表示与任务读出没有强制一致性**的结构事实。它是否是主要瓶颈仍需匹配读出实验，不能由源码直接确定效应量。

### 4.3 A2-R 的所有 anchor 共用同格同类 residual，缺少 anchor 质量分辨力

部署公式为：

```text
logit_new[a,c,u] = logit_base[a,c,u] + residual[c,u]
```

对固定位置 u、类别 c，任意两个 anchor a/b：

```text
logit_new[a,c,u] - logit_new[b,c,u]
  = logit_base[a,c,u] - logit_base[b,c,u]
```

所以该直接 residual **不能重排同格同类的不同尺寸/朝向 anchor**；它能改跨位置/跨类排序，但没有直接的框质量选择能力。
`anchor3d_head.py:446–513` 确认 residual 只加 `cls_score`，不加 bbox/direction 输出。
**限定**：RSSM 原来的 `output_proj(z)+feat` 仍可经共同特征影响回归；这不是「所有 z 路径都不能改框」。

一个对象附近的分类信号更强，如果落在错位格或支持低 IoU anchor，可能只提升坏框分数；这是源码支持的风险，**实际发生比例未测**。
同格 residual 的检测梯度还汇总多个 anchor 的正/负监督，可能与辅助中心监督冲突；梯度范数/夹角未测，不能当成已确认根因。

### 4.4 单纯放大 residual 不足以解释问题

已有同 checkpoint 读数（只读 GT 格命中代理，不是 AP）：
`×0:72% / ×1:76% / ×2:77% / ×4:76% / ×8:75% / ×1e6:71%`。
不是 residual 完全压不过原 head；但让它主导也没有更好。因此**没有证据支持先扫增益来修复**。

## 5. 实际 AP 的另一条证据：收益集中于部分类，且几何质量仍受限

| 构成项 | A2-R ep7–11 | B0 ep7–11 | Δ |
|---|---:|---:|---:|
| Car strict | 49.2452 | 46.9730 | +2.2722 |
| Truck strict | 24.1824 | 28.0924 | -3.9101 |
| Pedestrian loose | 27.5122 | 29.2998 | -1.7877 |
| Cyclist loose | 46.1897 | 49.8170 | -3.6273 |

Car +2.2722 被 Truck/Ped/Cyc 的负差抵消；不是各类都完全没收益。
Overall 的混合口径是 `(Car strict + Truck strict + Ped loose + Cyc loose)/4`。

同窗口 Overall：2D Δ **+0.1587**、BEV Δ **−0.4507**、3D Δ **−1.7632**。
Truck 3D strict **−3.9101**、loose **+1.5294**；Car 3D strict **+2.2722**、loose **+5.6716**。
这些读数提示：**容易成立的语义/粗匹配收益，没有等量转化为高 IoU 3D 框**。
但 strict/loose 的 PR 曲线也受分数排序、匹配与 NMS 影响；**不能只凭差值就认定是尺寸/高度/朝向哪一项坏了**。
与第 4 节的「只加类别、不直接加入框质量」结构风险相符，但尚不是预测级因果识别。

## 6. 哪些解释被削弱，哪些仍未知？

- **不是完全未接通**：zero_z/局部 residual 开关已有可测影响。
- **不能只怪采样与部署均值不同**：同一 val 20-clip、同一 eval 网络的两臂，z 的相对 mean-abs 变化 **33.45%**，语义图变化 **1.31%**；hit@1/ thr50 完全相同。只削弱该单次采样对这两个指标的解释，未检验多噪声 seed 或 AP。
- **局部 BN 模式不是充分解释**：同 eval 模式 train/val thr50 0.4355/0.0712；切换 z 路径 4 个 BN 后两侧分别 −0.0933/−0.0212，没有消除 split 差距。未全面排除其他 BN/数据分布因素。
- **KL 仍高度 clamped，但不能直接归因为 AP 不涨**：训练 ep11 logger 均值 clamped 0.9952。多数元素的直接 KL 梯度被截断；未 clamped 部分仍可能起作用，更未证明调 KL 会改善 AP。
- **M4 donor_transfer 不能独自证明无语义**：源码用 donor 整张图在 recipient GT 坐标处的类别与 donor 全局多数类比较；没有对象/空间对应约束。语义局部编码正确时，也不必在 recipient 的这些坐标输出 donor 多数类。保留原 FAIL，但不把这个 FAIL 当充分否定。
- **M4 聚合口径必须匹配**：残差 own_hit 按 clip 为 76.84%，同单位逐 clip 多数类 floor 为 69.18%（差 +7.66pt）；按 100 GT 格 pooled 为 71.00%，pooled floor 50.00%（差 +21.00pt）。两种加权总体与多数类基准均不同（逐 clip 多数类 vs 全局多数类），禁止混用为同一效应；不回改冻结门。
- **BN artifact 的参考 metadata 仍保留父臂 A 的数值**：本次只用 raw arms 与原始 paired delta，不采用 `eval_reproduces_frozen_gate` 的父臂比较标志，不因此改门。
- **随机状态必要性未证实**：语义信号也可能由确定性隐状态/额外监督得到；M2 同一头更换输入存在分布外问题，不能替代训练匹配的 deterministic/no-z 控制。

## 7. 最小因果补证：先量预测，再决定改哪个模块（本次均未执行）

当前 GPU5/6/7 现役训练不受干扰，训练队列不改。A2-R 成熟 checkpoint 可用后，在空闲窗口做：

1. **同一 checkpoint、同一 evaluator 的 full-val residual on/off**：两臂都用相同 RSSM 特征/框，只改变直接分类 residual。先做 identity；若用离线 harness，就两臂及 B0 都走该 harness，禁止与 EvalHook 混算（§51.5 已有差异）。
2. **存 NMS 前框与分数，做 score-only 对账**：按类/距离/回波组测真框进入 top-k 的比例、错误高分峰/FP、score–IoU 关系、NMS 前后 TP 丢失；将分类收益与几何/排序损害分开。IoU oracle 只诊断，不是推理方法。
3. **分解 3D 几何错误**：对同一候选分别 oracle 修 xy/z/size/yaw，看哪项限制 strict 3D AP，并保留匹配口径。若几何差但分类有效，才支持向几何取证/框质量读出转向。
4. **另做 z 整体路径干预**：直接 residual off 后原 `output_proj(z)` 仍在；所以 off 不能回答「z 是否必要」。检查 prior-only、区域/对象匹配的 z 干预与最终 AP；随机必要性最终需同容量确定性状态的配对多 seed 训练。
5. **仅在需要区分优化冲突时做梯度探针**：分别量 detection/semantic/recon/KL 对 z、h 及共享参数的梯度范数与夹角，不用标量 loss 占比代替。

可否证分支：
- on/off AP 几乎相同但 M3 好：主要是代理局部收益，未进入最终候选。
- on 提升 recall 却提高 FP、AP 反降：排序/质量耦合问题。
- on 对部分类有益、总体负：跨类收益抵消，需逐类/分组解释，不宣称全局机制成立。
- on/off 都弱且 IoU oracle headroom 大：候选几何/观测信息更值得优先修。
- matched deterministic 与 stochastic 同样好：不能把增益写成随机状态的独有贡献。

这批探针比直接再加 KL 权重、增益门或更深模块更能区分根因。新 geometry fusion 可改善观测，但只有上述输出级补证才允许将改善归因于 RSSM 的随机机制。

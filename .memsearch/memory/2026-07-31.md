- User 询问在 RSSM transition 中 `z_state`（及可选的 `z_state`）是否也需要做 warp（空间对齐）。
- Claude Code 从 ConvGRU 的计算原理分析，指出 `z_state` 和 `h_state` 共同拼接到 `x` 后送入 ConvGRU，ConvGRU 内部对拼接后的 `[x, h]` 做 3×3 空间卷积 —— 如果 `h_state` 做了 warp 而 `z_state` 没有，会导致同一个空间位置上两个特征来源指向不同目标/背景，产生错位噪声。
- Claude Code 认为 `z_state` 也应该做 warp，理由包括：`z_state` 参与空间卷积、当前代码中 `z_state` 实际是确定性的 feature map（`deterministic=True`），以及参数代价较小（约 1.2M 参数）。
- Claude Code 建议默认设置 `align_z_state=True`，并支持通过配置开关控制以进行消融实验。
